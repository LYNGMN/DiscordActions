# Google News 안전 수동 테스트 모드 설계

## 목적

오래된 데이터베이스 아티팩트가 없더라도 Google News 워크플로를 Discord 알림 폭주 없이 실제로 검증한다. Keyword, Top, Topic 워크플로를 각각 한 번 수동 실행하며 각 실행은 최신 기사 한 건만 전송한다.

## 검토한 접근

1. **수동 테스트 모드에서 최신 한 건만 전송하고 나머지를 기준선으로 저장한다.** 실제 Discord 전송과 URL 변환을 검증하면서 이후 실행이 과거 기사를 새 기사로 오인하지 않는다. 이 방식을 사용한다.
2. 기존 워크플로를 그대로 활성화한다. 변경은 적지만 DB가 없을 때 피드 전체가 전송될 수 있어 제외한다.
3. Discord 없이 로컬 변환만 검증한다. URL 변환은 확인할 수 있지만 GitHub Secrets, Actions, Discord 웹훅 연결을 검증하지 못해 보조 검증으로만 사용한다.

## 동작

- 세 워크플로의 `workflow_dispatch`에 `manual_test` 불리언 입력을 추가한다.
- 예약 실행에서는 `manual_test`가 항상 꺼져 기존 동작을 유지한다.
- 수동 테스트가 켜지면 아직 게시되지 않은 현재 피드 항목 중 발행일이 가장 최신인 한 건만 기존 처리 경로로 보낸다.
- 나머지 미게시 항목은 각 워크플로 DB의 `news_items` 테이블에 공통 열(`pub_date`, `guid`, `title`, `link`, `related_news`) 기준선으로 등록한다. 링크 변환이나 Discord 전송은 하지 않는다.
- 최신 한 건의 변환 또는 Discord 전송이 실패하면 기존 오류 처리대로 실행을 실패시킨다. 실패를 성공으로 숨기지 않는다.
- 처리할 미게시 항목이 없으면 성공 종료하며 중복 알림을 보내지 않는다.
- DB 아티팩트에는 기준선과 URL 변환 캐시가 함께 보존된다.

## 공통 코드 경계

새 공통 모듈은 다음 한 가지 책임만 가진다.

- `prepare_manual_test_items(items, db_path, enabled)`
  - 비활성일 때 입력 순서를 그대로 반환한다.
  - 활성일 때 최신 항목 한 건을 반환한다.
  - 반환하지 않은 항목의 공통 열을 `news_items`에 `INSERT OR IGNORE`로 저장한다.

세 기존 스크립트는 DB 초기화와 미게시 항목 선별 이후 이 함수를 호출한다. Discord 메시지 포맷, 필터, 원문 URL 변환, 저장 순서는 변경하지 않는다.

## 운영 절차

1. 변경을 별도 브랜치에서 테스트하고 Draft PR로 게시한다.
2. 검토와 별도 병합 승인 후 Squash로 `main`에 반영한다.
3. 예약 경계 직후의 안전 구간에서 워크플로 하나를 활성화한다.
4. `manual_test=true`로 수동 실행하고 완료 직후 워크플로를 다시 비활성화한다.
5. 실행이 다음 예약 경계에 가까워지면 취소하고 비활성화한다. 성공 시 Discord 최신 기사 한 건 전송을 확인한 뒤 다음 워크플로로 진행한다.

## 테스트

- 최신 항목 한 건 선택과 나머지 GUID 기준선 등록
- 비활성 모드에서 입력과 DB가 바뀌지 않음
- 빈 입력의 안전한 종료
- 기존 GUID를 덮어쓰지 않음
- 세 스크립트가 공통 준비 함수를 사용함
- 세 워크플로에 수동 테스트 입력과 환경 변수가 존재함
- 기존 Google News URL resolver 테스트 전체 회귀
- Python 컴파일과 GitHub Actions 테스트

## 제외 범위

- 30분 예약 주기 변경
- Google News 워크플로의 영구 재활성화
- Discord 메시지 형식 변경
- YouTube 워크플로 변경
- 기존 액션 버전 고정이나 Python 업그레이드
